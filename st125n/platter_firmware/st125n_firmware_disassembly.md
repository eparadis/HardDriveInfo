# ST-125N service firmware: 8052 identification and mapped disassembly

## Artifacts

- Input: `captures/st125n-startup/st125n-program.bin`
- Size: 8,192 bytes (32 256-byte sectors)
- SHA-256:
  `ca3070bcfa78fa32f9c6bfa824932fc90aa475d22ae7aef6c77bda545682260d`
- Corrected mapped listing: `st125n-program.mapped.disasm51.asm`
- Historical offset-zero listing: `st125n-program.disasm51.asm`
- Addressed selector-02/03 artifacts and layered listings:
  `st125n_service_cylinder_overlays.md`
- Three-drive comparison: `st1xxn_service_overlay_comparison.md`
- Symbol include: `seagate_8052_symbols.inc`
- Disassembler: `disasm51` 1.0.1

The corrected listing was generated by prefixing the recovered image with
`0x4000` bytes of disposable `0xff` padding, entering the image at addresses
`0x4000`, `0x4003`, `0x4013`, `0x40eb`, `0x4110`, and `0x417e`, and then
omitting the padding from the saved listing. This is necessary because
`disasm51` 1.0.1's `--offset` adjusts absolute operands but does not relocate
the program counters printed in the listing.

An equivalent disassembler invocation against that mapped analysis image is:

```sh
uv tool run disasm51 \
  --include docs/investigations/seagate_8052_symbols.inc \
  --entry 0x4000 \
  --entry 0x4003 \
  --entry 0x4013 \
  --entry 0x40eb \
  --entry 0x4110 \
  --entry 0x417e \
  /tmp/st125n-program-mapped-at-4000.bin \
  > docs/investigations/st125n-program.mapped.disasm51.asm
```

The saved listing renames automatically discovered targets below `0x2000` with
a `maskrom_` prefix and deliberately excludes attempted disassembly of that
unavailable address range. It remains an analysis aid, not rebuildable source;
recursive traversal can still mistake indirect dispatch tables for code.

## Processor identification

This is 8052 code, not 6502 or 8085 code. Evidence includes the
`LJMP` vector encoding (`02 high low`), `LCALL` (`12 high low`), `MOV DPTR`
(`90 high low`), `MOVX`, accumulator/B-register multiplication, bit-addressed
branches, and `RETI` at file offset `0x017c` (code address `0x417c`).

The controller is now identified from the PCB as a Signetics
`SCN8052HCCA44`, additionally marked `80166-501` and
`2223N079215KB`. The `SCN8052HCCA44` is a 44-pin, 12 MHz, factory-mask-ROM
8052 with 8 KiB of internal program ROM, 256 bytes of internal RAM, and Timer
2. The `9215` portion of the longer marking is consistent with the surrounding
board date codes and is probably 1992 week 15, but that decoding is an
inference rather than a manufacturer-confirmed field definition. Likewise,
`80166-501` is probably Seagate's number for the programmed/custom part, not a
Signetics catalog number.

The larger 8052 internal RAM makes the observed initial stack pointer of
`0xbf` unremarkable. The second-pass symbol file adds the standard 8052 Timer 2
registers and interrupt vector. Direct addresses `0xd2` and `0xe4` are still
not standard 8052 byte SFRs; they may be custom aliases, ASIC-related source
conventions, or false code paths through data and remain unnamed.

No use of the standard Timer 2 SFRs or its `0x002b` interrupt vector was found
in the recursively discovered overlay code. Timer 2 may be configured wholly
by the on-chip ROM, or unused by this firmware path; absence from an incomplete
recursive disassembly is not proof that the peripheral is unused.

## Address-space model

The part identification resolves the previously ambiguous address model:

- `0x0000-0x1fff` is the 8052's 8 KiB on-chip mask ROM;
- the recovered 8 KiB disk image is loaded as external program code at
  `0x4000-0x5fff`;
- code address = file offset + `0x4000`;
- calls below `0x2000` are unresolved calls into the on-chip mask ROM;
- calls and jumps in `0x4000-0x5fff` refer to routines or data within the
  recovered overlay.

The first bytes of the disk image are therefore an overlay entry table, not
the processor's hardware reset and interrupt vectors. File offset `0x0000`
jumps to overlay entry `0x417e` (file offset `0x017e`); offsets `0x0003` and
`0x0013` jump to `0x40eb` and `0x4110`. The old offset-zero listing remains
useful for byte lookup, but its `RESET`/interrupt-vector names and its
interpretation of `0x40xx-0x5xxx` targets as resident ROM are superseded.

Within the code paths found in this pass, the ST-125N overlay references 30
distinct destinations below `0x2000`. These are now left as unresolved
`maskrom_XXXX` symbols instead of being followed into nonexistent bytes of the
service-track image.

## Initial observations

The routine at `0x417e` (file offset `0x017e`) initializes state in external
data memory near `0x5b02`, calls a mixture of overlay and internal mask-ROM
routines, reads more state near `0x5b67` and `0x5b6c`, and then enters
command-processing logic. The formerly unidentified `MOVX` addresses are now
matched to the Adaptec controller register map: `0x8050`, `0x8052`, `0x8053`,
and `0x8059` are AIC-300/301 host-data, host-interface, DMA, and reset
registers; `0x8070` is the external buffer-data window; and `0x807e` is the
AIC-010 general-purpose I/O register. See
`docs/investigations/adaptec_aic_register_map.md`.

The behavior confirms the logical roles. The overlay pulses the
AIC-300/301-compatible reset through register `59h`, reads the documented
`SELECT IN`/`BUSY IN` bits in register
`52h`, performs SCSI arbitration through that register, enables target mode in
DMA register `53h`, exchanges bytes through host-data register `50h`, and
tests board signals through the AIC-010-compatible GPIO register `7Eh`. Its
command routine reads the command byte through external buffer window `70h`.

The PCB markings now identify the physical implementations. A Cirrus Logic
`11739-502 9050 B 00469` occupies the AIC-300/301-compatible buffer-controller
position. An unbranded `11740-511 HS9222 60566.1`, marked in the same style as
other Seagate-house parts on the board, occupies the AIC-010-compatible
position. PCB placement and the overlay's register-level behavior establish
these functional roles; they do not yet establish whether either device was a
licensed second source, a Seagate custom part, or a compatible derivative.

Unlike the ST-138N and ST-157N mapped passes, the currently discovered ST-125N
paths do not expose the buffer-controller pointer registers or the
AIC-010-compatible ECC/status registers. Those operations may reside in the
different `80166-501` internal mask ROM or behind indirect paths not found by
recursive disassembly.

Internal byte `0x44` holds the current SCSI opcode and is repeatedly compared
with `0x03`, `0x04`, `0x07`, `0x0a`, `0x11`, `0x16`, `0x17`, and `0x2a`.
The product manual identifies `0x11` as READ USAGE COUNTER. The nearby
`0x18` comparison is not against byte `0x44`: it follows recognition of
FORMAT UNIT (`0x04`) and tests the next saved CDB byte, so it is a format
option/parameter rather than an opcode.

Bytes from file offset `0x1d56` through `0x1fff` (code addresses
`0x5d56-0x5fff`) are a uniform `0x6c` fill (682 bytes). The preceding area
contains dense four-byte tables through `0x1d55`,
so the useful image content is not purely executable code and ends in table
data rather than at a function boundary.

## What is still needed

1. Locate documentation or establish pin-level correspondence for the Cirrus
   `11739-502` and Seagate-style `11740-511`. Their logical roles are now
   established, but their implementation provenance is not.
2. Recover the internal mask ROM corresponding to probable Seagate part
   `80166-501`. It is inside the SCN8052, not a separate resident-ROM device;
   calls below `0x2000` cannot be resolved from the service-track image alone.
3. Locate and describe the indirect dispatch tables, then regenerate the
   listing with `--entry` or `--indirect` ranges so data/code separation is
   reliable.
4. Trace the now-recovered selector-02 and selector-03 components back to the
   `80166-501` mask-ROM loader and determine the command or test path that
   selects each layer.
